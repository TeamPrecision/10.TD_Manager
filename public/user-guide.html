01

Accounts & Roles

There are three role levels in TD Manager. Each role controls which pages are visible and what actions can be performed.

Name Email Role Access
Leader leader@td.local Leader Full access to all pages and actions
Debug 1 debug1@td.local Debug Projects, Tester Status, Purchasing (request only), Customer Items (add only), Activity Log, Tickets
Debug 2 debug2@td.local Debug
Coding 1 coding1@td.local Coding Same as Debug
Coding 2 coding2@td.local Coding
Fixture fixture@td.local Fixture Projects, Tester Status, Purchasing (request only), Customer Items (add only), Activity Log, Tickets
Purchasing purchasing@td.local Purchasing Projects (view only), Tester Status, Purchasing (full), Activity Log, Tickets
Note: Access is enforced both on the sidebar (which hides unavailable pages) and on the server — direct URL access to restricted pages is blocked.
02

Logging In

  • Open the system URL in your browser. You will be taken to the Login page.

  • Enter your email and password, then click Login.

  • After a successful login you are redirected to the Projects page.

  • To log out, click your name/avatar at the bottom of the left sidebar, then click Logout.

Tip: If you see "Invalid credentials", double-check that Caps Lock is off and you are using the correct email address.
03

Projects

The Projects page is the main dashboard. It lists all active projects with their progress, current stage, and key dates.

📋

Project Table

Shows all projects with fixture, current process stage, progress bar, delivery date, and open ticket count. Click any project name to open its detail page.

🔍

Search & Filter

Use the search bar to find projects by name, customer, or fixture. Use the Filter button for column-level filters. Click stage pills at the top to filter by process stage.

➕

New Project (Leader)

Leaders can click + New Project to create a project. Enter the project name and customer, then save.

📊

Export

Use Copy to copy the table as tab-separated data (paste into Excel), or Image to download a screenshot of the table.

Inside a Project

Clicking a project opens its detail page with two main sections:

  • Process List — tracks each stage (RFQ → Delivered). Click a stage status dot to mark it Done/Pending. Add comments and attach file/SVN links per stage.
  • Fixture Manager — manage fixtures and FGs (Functional Groups) for the project. Add, rename, or delete fixtures and FGs.
Note: Purchasing members see the project detail in read-only mode — no edits are allowed.
04

Tickets

The Tickets page tracks bugs, hardware issues, software issues, requests, and other problems linked to a project.

🎫

Creating a Ticket

Click + New Ticket. Fill in the title, project, type, and priority. Add a description and an optional deadline, then click Create.

👤

Assigning (Leader)

Drag a team member's avatar from the Drag to Assign strip and drop it onto any ticket row. Hover the avatar on a row and click ✕ to unassign.

🔄

Changing Status

Click the status badge on a ticket you are assigned to. Choose the next state. The normal flow is: Open → In Progress → Resolved.

📈

Analyze

Click Analyze to see charts summarising ticket volume, type distribution, and priority across all projects.

Ticket Statuses

  • Open — Awaiting action (Leader must start it)
  • In Progress — Being worked on
  • Resolved — Fixed and closed
  • Rejected — Not accepted (Leader only)
External reports: The Report a ticket link on the login page lets anyone submit a ticket without logging in — for department staff or external reporters.
05

Purchasing

Tracks all components and parts ordered for the projects — quantities, prices, PR numbers, sources, and delivery status.

➕

Add Item (Leader / Purchasing)

Click Add Item to register a new component. Enter the name, PR number, source/vendor, quantity, price, and initial status.

📦

Withdraw (Request Stock)

Click the arrow icon on any item to withdraw stock for a specific project and fixture. Enter quantity and optional notes. Available to all members.

🔄

Change Status (Leader / Purchasing)

Click the status badge on an item to toggle between Ordered and Received. Add a comment for the audit trail.

🗑️

Delete Item (Leader / Purchasing)

Click the trash icon to delete an item. A comment is required explaining the reason for removal.

Remaining column: Shows stock left after all withdrawals. Red = fully issued, Yellow = partially issued, Green = full stock available.
06

Customer Items

Tracks customer-provided equipment and sample boards received for testing.

  • Click + Add Item or + Add Sample Board to register a new item. Link it to a project and fixture.

  • Items start as Pending. When work begins, a Leader changes the status to In Progress.

  • Once testing is complete, the Leader sets the status to Received. This is a final state — it cannot be reversed by anyone.

  • Click an item row to expand it and view its full history of comments and status changes.

Permissions: Debug, Coding, and Fixture members can add items but cannot change status or delete. Only the Leader can change status or delete items.
07

Activity Log

A read-only audit trail of all significant actions taken in the system — project updates, status changes, item additions, ticket movements, and more.

Use the filters at the top to narrow results by date range, user, entity type, or action. The log is sorted newest first.

Note: Every status change includes the comment left by the user, providing full context for each transition.
08

Fixture

Available to Leader only. This page provides a global view of all fixtures and their associated FGs across all projects.

Use it to quickly see which fixtures exist, which FGs they contain, and navigate directly into the relevant project detail page.

09

Tester Status

Shows the live status of all registered tester PCs — whether they are running, which FG they are testing, pass/fail counts, and last heartbeat time.

  • Running — Actively performing a test cycle
  • Offline — Not seen recently

The page auto-refreshes. Each tester card shows its PC name, AnyDesk ID, current project/FG, and cycle pass/fail counts.
